# REST API салона красоты

Контракт опирается на [модель данных](./data_model.md) и [сценарии пользователей](./user_stories.md).

## Общие соглашения

- Базовый префикс маршрутов — `/api`. Параметры в фигурных скобках обязательны и передаются в пути. Все идентификаторы — положительные целые числа. Query-параметры необязательны, если явно не указано обратное.
- Роли учётных записей — `client`, `master`, `admin`. Доступ «все» включает гостей. Защищённые маршруты принимают заголовок `Authorization: Bearer <access_token>`. JWT содержит идентификатор пользователя `userId`. Сервер проверяет подпись, срок действия и актуальную роль в `users`. Если токен передан на публичный маршрут каталога или доступности, сервер проверяет его на тех же условиях. Регистрация и вход используют поля запроса.
- Запросы с JSON-телом передают `Content-Type: application/json`. Загрузка фото использует `multipart/form-data`. Для `PATCH` указывается хотя бы одно разрешённое поле, пропущенные поля сохраняют прежнее значение. Неизвестные поля тела и параметры запроса отклоняются. `password_hash` хранится на сервере и исключается из ответов.
- Цены — целые рубли, `price >= 0`. Длительность услуги — положительное целое число минут. Для списков пользователей, мастеров и записей `limit` по умолчанию равен 20, допустимы значения 1–100, `offset` по умолчанию равен 0 и должен быть неотрицательным.
- У мастера, услуги и связи мастера с услугой допустимы переходы `active ↔ inactive`. Повторная установка текущего статуса допустима. Эффективная доступность для новой записи требует `active` во всех трёх строках и роли `master` у владельца профиля. Статусы меняются независимо. Деактивация и изменение рабочих часов влияют на новые бронирования. Уже созданные записи сохраняют время, цену и статус.

## 1. Аутентификация

### POST /api/auth/register — зарегистрировать клиента

**Доступ** — все. **Path** — нет. **Query** — нет.

**JSON запроса** — все поля обязательны. `login`, `first_name` и `last_name` должны быть непустыми и содержать до 100 символов. Пароль должен быть непустым, сервер сохраняет его хеш. Сервер назначает роль `client` и выдаёт JWT.

```json
{
  "first_name": "Анна",
  "last_name": "Иванова",
  "login": "anna_ivanova",
  "password": "ExamplePassword123!"
}
```

**JSON ответа**

```json
{"access_token": "<jwt>"}
```

**Коды** — `201` аккаунт создан и токен выдан, `400` неверное тело, `409` логин уже занят.

### POST /api/auth/login — войти в систему

**Доступ** — все. **Path** — нет. **Query** — нет.

**JSON запроса** — обязательны `login` и `password`.

```json
{"login": "anna_ivanova", "password": "ExamplePassword123!"}
```

**JSON ответа**

```json
{"access_token": "<jwt>"}
```

**Коды** — `200` токен выдан, `400` неверное тело, `401` неверный логин или пароль.

## 2. Пользователи

### GET /api/users — получить список пользователей

**Доступ** — `admin`. **Path** — нет. **Query** — `role` (`client`, `master`, `admin`), `limit`, `offset`. Сортировка по возрастанию `id`.

**JSON запроса** — отсутствует. **JSON ответа**

```json
[
  {"id": 12, "login": "anna_ivanova", "first_name": "Анна", "last_name": "Иванова", "role": "client"}
]
```

**Коды** — `200` список получен, `400` неверные фильтры или пагинация, `401` ошибка аутентификации, `403` требуется роль администратора.

### GET /api/users/{id} — получить пользователя

**Доступ** — `admin`. **Path** — `id` пользователя. **Query** — нет.

**JSON запроса** — отсутствует. **JSON ответа**

```json
{"id": 12, "login": "anna_ivanova", "first_name": "Анна", "last_name": "Иванова", "role": "client"}
```

**Коды** — `200` пользователь найден, `400` неверный `id`, `401` ошибка аутентификации, `403` требуется роль администратора, `404` пользователь не найден.

### PATCH /api/users/{id}/role — изменить роль

**Доступ** — `admin`. **Path** — `id` пользователя. **Query** — нет.

**JSON запроса** — обязательное поле `role` со значением `client`, `master` или `admin`.

```json
{"role": "master"}
```

**JSON ответа**

```json
{"id": 27, "login": "maria_petrova", "first_name": "Мария", "last_name": "Петрова", "role": "master"}
```

Изменение роли сохраняет существующие записи и профиль мастера. Права доступа и доступность профиля для новых бронирований определяются по актуальной роли.

**Коды** — `200` роль установлена, `400` неверный `id` или JSON, `401` ошибка аутентификации, `403` требуется роль администратора, `404` пользователь не найден.

## 3. Мастера

### GET /api/masters — получить список мастеров

**Доступ** — все. **Path** — нет. **Query** — `service_id` для фильтрации по услуге, `limit`, `offset`. Администратору также доступен `status=active|inactive|all`. По умолчанию — `active`.

Гость, клиент и мастер видят только активные профили пользователей с ролью `master`. Для них фильтр `service_id` дополнительно требует активную услугу и активную связь. Для администратора достаточно существующей связи с услугой, а фильтр по статусу профиля применяется отдельно. Сортировка по возрастанию `id`.

**JSON запроса** — отсутствует. **JSON ответа**

```json
[
  {"id": 4, "first_name": "Мария", "last_name": "Петрова", "experience": 5, "description": "Парикмахер", "photo_url": null, "status": "active"}
]
```

**Коды** — `200` список получен, `400` неверный фильтр или параметры пагинации, `401` передан недействительный токен, `403` фильтр `status` передан без роли администратора.

### GET /api/masters/{id} — получить карточку мастера

**Доступ** — все. Администратор видит профили с любым статусом. Для остальных действуют те же правила видимости, что и в списке мастеров. **Path** — `id` профиля мастера. **Query** — нет.

**JSON запроса** — отсутствует. **JSON ответа**

```json
{"id": 4, "first_name": "Мария", "last_name": "Петрова", "experience": 5, "description": "Парикмахер", "photo_url": null, "status": "active"}
```

**Коды** — `200` карточка получена, `400` неверный `id`, `401` передан недействительный токен, `404` профиль отсутствует или скрыт из публичного каталога.

### POST /api/masters — создать профиль мастера

**Доступ** — `admin`. **Path** — нет. **Query** — нет.

**JSON запроса** — обязательны `user_id` и `experience` (целое число полных лет, от 0). `description` необязательно и допускает `null`. При создании `photo_url` равен `null`. После создания профиля администратор может загрузить фото через маршрут из раздела «Фотографии мастеров». Новый профиль получает статус `active`, свободные слоты появятся после настройки рабочих часов и назначения услуги.

```json
{"user_id": 27, "experience": 5, "description": "Парикмахер"}
```

**JSON ответа**

```json
{"id": 4, "first_name": "Мария", "last_name": "Петрова", "experience": 5, "description": "Парикмахер", "photo_url": null, "status": "active"}
```

**Коды** — `201` профиль создан, `400` неверное тело, `401` ошибка аутентификации, `403` требуется роль администратора, `404` учётная запись не найдена, `409` у пользователя другая роль или профиль уже существует.

### PATCH /api/masters/{id} — изменить профиль или статус мастера

**Доступ** — `admin`. **Path** — `id` профиля мастера. **Query** — нет.

**JSON запроса** — поля `experience`, `description`, `status`. Для `experience` и `description` действуют ограничения из запроса на создание профиля. Фото меняется через отдельный маршрут. Для вывода мастера из каталога используется `status: "inactive"`. Связь профиля с пользователем сохраняется.

```json
{"experience": 6, "status": "inactive"}
```

**JSON ответа**

```json
{"id": 4, "first_name": "Мария", "last_name": "Петрова", "experience": 6, "description": "Парикмахер", "photo_url": null, "status": "inactive"}
```

**Коды** — `200` профиль обновлён, `400` неверный `id` или JSON, `401` ошибка аутентификации, `403` требуется роль администратора, `404` профиль не найден.

### GET /api/masters/{id}/working-hours — получить рабочие интервалы

**Доступ** — `admin` для любого мастера, `master` для собственного профиля (включая неактивный). **Path** — `id` профиля мастера. **Query** — нет.

**JSON запроса** — отсутствует. **JSON ответа** — массив в порядке дня недели и времени начала.

```json
[
  {"id": 31, "master_id": 4, "day_of_week": 1, "start_time": "09:00:00", "end_time": "13:00:00"},
  {"id": 32, "master_id": 4, "day_of_week": 1, "start_time": "14:00:00", "end_time": "18:00:00"}
]
```

**Коды** — `200` интервалы получены, `400` неверный `id`, `401` ошибка аутентификации, `403` роль не имеет доступа к рабочим часам, `404` профиль отсутствует или находится вне области доступа мастера.

### PUT /api/masters/{id}/working-hours — заменить недельное расписание

**Доступ** — `admin`. **Path** — `id` профиля мастера. **Query** — нет.

**JSON запроса** — `intervals` содержит полный набор рабочих интервалов. У каждого элемента обязательны три поля из примера. `day_of_week` — целое число от 1 (понедельник) до 7 (воскресенье). Время окончания позже начала в пределах одного дня. Интервалы дня не пересекаются. День без интервалов считается выходным. Пустой массив очищает расписание. Замена выполняется целиком в одной транзакции.

```json
{
  "intervals": [
    {"day_of_week": 1, "start_time": "09:00:00", "end_time": "13:00:00"}
  ]
}
```

**JSON ответа** — итоговые интервалы в том же формате и порядке, что у `GET`.

```json
[
  {"id": 31, "master_id": 4, "day_of_week": 1, "start_time": "09:00:00", "end_time": "13:00:00"}
]
```

**Коды** — `200` расписание сохранено, `400` неверный `id`, поля или пересекающиеся интервалы, `401` ошибка аутентификации, `403` требуется роль администратора, `404` мастер не найден.

### PUT /api/masters/{id}/services/{service_id} — назначить услугу или изменить статус связи

**Доступ** — `admin`. **Path** — `id` профиля мастера, `service_id` услуги. **Query** — нет.

**JSON запроса** — обязательное поле `status` со значением `active` или `inactive`.

```json
{"status": "active"}
```

**JSON ответа**

```json
{"id": 19, "master_id": 4, "service_id": 7, "status": "active"}
```

При первом запросе сервер создаёт строку `master_service`. Для существующей пары обновляется только статус, идентификатор связи сохраняется. Пара `(master_id, service_id)` уникальна.

**Коды** — `201` связь создана, `200` статус существующей связи установлен, `400` неверные идентификаторы или JSON, `401` ошибка аутентификации, `403` требуется роль администратора, `404` мастер или услуга не найдены.

### GET /api/masters/{id}/services — получить услуги мастера

**Доступ** — все. **Path** — `id` профиля мастера. **Query** — нет.

Администратор получает все связи указанного мастера, включая неактивные. Гость, клиент и мастер получают только доступные для бронирования сочетания. `id` в каждом элементе — идентификатор `master_service`, который используется при поиске слотов и создании записи.

**JSON запроса** — отсутствует. **JSON ответа**

```json
[
  {
    "id": 19,
    "master_id": 4,
    "service_id": 7,
    "status": "active",
    "service": {"id": 7, "name": "Женская стрижка", "description": "Стрижка коротких волос", "price": 1500, "duration_minutes": 60, "status": "active"}
  }
]
```

**Коды** — `200` список получен, `400` неверный `id`, `401` передан недействительный токен, `404` профиль отсутствует или скрыт из публичного каталога.

Администратор видит услуги, для которых существует связь с выбранным мастером, включая отключённые связи. Фильтр по статусу услуги применяется отдельно. ### GET /api/services/{id} — получить карточку услуги

{"id": 7, "name": "Женская стрижка", "description": "Стрижка коротких волос", "price": 1500, "duration_minutes": 60, "status": "active"}

### POST /api/services — создать услугу

**Доступ** — `admin`. **Path** — нет. **Query** — нет.

**JSON запроса** — обязательны `name`, `price`, `duration_minutes`. `name` — непустая после обрезки пробелов строка до 255 символов. `description` необязательно и допускает `null`. Сервер присваивает `status: "active"`.

```json
{"name": "Маникюр с покрытием", "description": null, "price": 2000, "duration_minutes": 90}
```

**JSON ответа**

```json
{"id": 8, "name": "Маникюр с покрытием", "description": null, "price": 2000, "duration_minutes": 90, "status": "active"}
```

**Коды** — `201` услуга создана, `400` неверное тело, `401` ошибка аутентификации, `403` требуется роль администратора.

### PATCH /api/services/{id} — изменить услугу или её статус

**Доступ** — `admin`. **Path** — `id` услуги. **Query** — нет.

**JSON запроса** — поля `name`, `description`, `price`, `duration_minutes`, `status`. Ограничения полей такие же, как при создании. `status: "inactive"` выводит услугу из публичного каталога и закрывает бронирование у всех мастеров. Изменение цены или длительности применяется к новым записям. В существующих записях сохраняются `price` и `end_time`, зафиксированные при бронировании.

```json
{"price": 2200, "duration_minutes": 100}
```

**JSON ответа**

```json
{"id": 8, "name": "Маникюр с покрытием", "description": null, "price": 2200, "duration_minutes": 100, "status": "active"}
```

**Коды** — `200` услуга обновлена, `400` неверный `id` или JSON, `401` ошибка аутентификации, `403` требуется роль администратора, `404` услуга не найдена.

## 5. Записи

### Правила бронирования и статусы

- Новая запись получает статус `planned`. Сервер берёт цену из `service.price` и вычисляет `end_time = start_time + service.duration_minutes`. Мастер и услуга определяются через `master_service_id`.
- Начало записи должно быть в будущем. Весь интервал должен помещаться в один рабочий интервал мастера. Временные интервалы имеют вид `[start_time, end_time)`. Начать новую запись можно точно в момент окончания предыдущей. Пересечение есть, если начало каждого интервала раньше конца другого.
- Пересечения проверяются по всем услугам одного мастера. В проверке участвуют записи `planned` и `completed`. Отмена освобождает интервал. Поиск слотов показывает доступность на момент запроса. При бронировании сервер повторно проверяет роли, статусы, график и пересечения в транзакции.
- Создание записи, обновление рабочих часов и изменения доступности должны согласованно блокировать затронутые ресурсы до конца транзакции. Смена роли, изменение услуги и переходы статуса записи используют те же правила синхронизации для общих ресурсов. Это позволяет сохранить условия бронирования при одновременных запросах, в том числе когда у мастера ещё нет записей.
- При чтении записи `price`, `start_time` и `end_time` берутся из `appointment`. Имена и название услуги берутся из связанных строк даже после деактивации каталога. Поля `client`, `master` и `service` в JSON собираются из существующих таблиц.

| Переход | Кто может выполнить | Когда разрешён |
| --- | --- | --- |
| `planned → cancelled` | Владелец записи с ролью `client` | Строго до `start_time`. |
| `planned → cancelled` | `admin` | Пока запись запланирована. Администратор может обработать и пропущенное посещение. |
| `planned → completed` | `admin` | С момента `end_time`, после подтверждения оказания услуги. |

`completed` и `cancelled` — конечные статусы. Повторный запрос текущего конечного статуса от пользователя с соответствующим правом возвращает `200`. Для переноса посещения клиент отменяет прежнюю запись и создаёт новую по правилам бронирования.

### GET /api/appointments/availability — получить свободное время

**Доступ** — все. **Path** — нет. **Query** — обязательны `master_service_id` и `date` в часовом поясе салона. Дата должна быть сегодняшней или будущей.

Сервер строит варианты начала с шагом 15 минут от начала каждого рабочего интервала выбранного дня. В ответ входят только будущие слоты, которые вмещают услугу и свободны по правилам бронирования. Один слот соответствует одному варианту начала. Варианты могут пересекаться между собой. Сортировка по времени начала.

**JSON запроса** — отсутствует. **JSON ответа**

```json
{
  "master_service_id": 19,
  "date": "2027-03-15",
  "slots": [
    {"start_time": "2027-03-15T10:00:00+08:00", "end_time": "2027-03-15T11:00:00+08:00"},
    {"start_time": "2027-03-15T10:15:00+08:00", "end_time": "2027-03-15T11:15:00+08:00"}
  ]
}
```

## 6. Фотографии мастеров

У каждого мастера может быть одна текущая фотография. Сервер хранит файл в файловом хранилище, а в `masters.photo_url` записывает HTTPS-адрес длиной до 2048 символов. Карточка и список мастеров возвращают этот адрес или `null`. URL фотографии из публичной карточки открывается без токена. Загружать, заменять и удалять фото может только администратор.

### POST /api/masters/{id}/photo — загрузить или заменить фото

**Доступ** — `admin`, для профиля с любым статусом. **Path** — `id` профиля мастера. **Query** — нет.

**Тело запроса** — `multipart/form-data` с одним обязательным полем `photo`, содержащим один файл. Допустимые форматы — JPEG, PNG и WebP. Максимальный размер файла — 5 МиБ (5 242 880 байт). Сервер проверяет фактический формат по содержимому и проверяет, что изображение декодируется.

```bash
curl -X POST "https://salon.example/api/masters/4/photo" \
  -H "Authorization: Bearer <access_token>" \
  -F "photo=@portrait.webp;type=image/webp"
```

Сервер сохраняет новый файл под новым именем и обновляет `photo_url`. Если сохранение файла или обновление ссылки завершается ошибкой, прежнее фото остаётся в профиле. После обновления ссылки сервер удаляет прежний файл из хранилища салона. Если запись ссылки не удалась, новый файл удаляется.

**JSON ответа**

```json
{
  "master_id": 4,
  "photo_url": "/media/masters/4/portrait-a8f2.webp"
}
```

**Коды** — `200` фото загружено или заменено, `400` неверный `id`, некорректная форма или передано количество файлов, отличное от одного, `401` ошибка аутентификации, `403` требуется роль администратора, `404` профиль не найден, `413` файл превышает допустимый размер, `415` запрос передан с другим типом содержимого или формат файла не поддерживается, `500` ошибка сохранения файла или ссылки.

### DELETE /api/masters/{id}/photo — убрать фото

**Доступ** — `admin`, для профиля с любым статусом. **Path** — `id` профиля мастера. **Query** — нет.

**JSON запроса** — отсутствует. **JSON ответа** — отсутствует.

Сервер устанавливает `masters.photo_url = null`. Файл из хранилища салона удаляется после сохранения изменений в профиле. Если фото уже отсутствует, результат тот же.

Загрузка и удаление для одного мастера должны согласованно обновлять ссылку. При сбое очистки хранилища сервер повторяет удаление файла, на который больше не ссылается профиль.

**Коды** — `204` фото убрано или уже отсутствует, `400` неверный `id`, `401` ошибка аутентификации, `403` требуется роль администратора, `404` профиль не найден, `500` ошибка обновления профиля.
